# СВОД — портал приёмки проектной документации

Комплект от бюро загружается → портал показывает состав томов, флаги готовности
к проверке и сводную номенклатуру объекта. Ни одного вызова модели: всё
детерминированно, из спецификаций и штампов листов.

Поверх существующего пайплайна `agent/`, без его переписывания. Между ними один
фасад — `agent/api.py`. CLI `python -m agent.run` продолжает работать.

Планы: `PORTAL_PLAN.md` (продукт), `AGENT_PLAN.md` (агентская часть).

## Что делает первая версия

- Загрузка томов PDF: браузер льёт файл прямо в хранилище по подписанной ссылке.
- Разбор в очереди с постадийным прогрессом («разбор спецификации, лист 84 из 213»).
- **Состав комплекта**: листов в томе, разбивка по типам, флаги готовности
  (спецификация найдена, кабельный журнал есть, ведомости освещения нет,
  17 листов нечитаемы).
- **Номенклатура объекта**: сводная по всем томам, поиск, фильтр по разделу,
  отметки «без марки», «дубль между разделами», «исключено изменением».
- Выгрузка в Excel в стилях отчёта сверки.

Чего нет намеренно: сверки с чертежами, замечаний, PDF-вьюера, ролей, **входа**.
Портал открыт любому, кто знает адрес — это осознанный размен на день разработки,
и его надо закрыть до первого реального проекта заказчика.

## Контур

```
браузер ──presigned PUT──> R2 (файлы)
   │
   └── web (FastAPI+HTMX) ──> Redis/RQ ──> worker ──> agent/api.py ──> Postgres
```

Веб никогда не открывает PDF сам. Прогресс пишется в таблицу `run`, а не в Redis:
перезапуск воркера не теряет историю.

## Деплой на Render

1. **Залить репозиторий на GitHub** (`git push`; первый коммит уже сделан).

2. **Создать бакет** в Cloudflare R2 (или B2/S3) и API-токен с правами на чтение
   и запись. Браузер грузит файл прямо в бакет, поэтому бакету нужен CORS:

   ```json
   [{"AllowedOrigins": ["https://svod-web.onrender.com"],
     "AllowedMethods": ["PUT"],
     "AllowedHeaders": ["content-type"],
     "MaxAgeSeconds": 3600}]
   ```

   Адрес в `AllowedOrigins` — тот, который выдаст Render после первого деплоя.
   Без этой настройки загрузка будет молча падать в браузере.

3. **Render → New → Blueprint**, указать репозиторий. `render.yaml` поднимет
   четыре сервиса: веб (0.5c-512mb), воркер (1c-2g), Postgres, Key Value.

4. **Заполнить переменные** группы `svod-config` (они помечены `sync: false`):
   `S3_BUCKET`, `S3_ENDPOINT` (`https://<account_id>.r2.cloudflarestorage.com`),
   `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`.

5. Открыть адрес веб-сервиса. Миграции применяются сами при старте, под
   advisory lock — веб и воркер стартуют одновременно и не мешают друг другу.

Ориентир по стоимости: web $7 + worker $25 + Postgres ~$6 + Key Value $0 +
R2 ~$1 ≈ **$40/мес**. Воркеру нужен именно 2 ГБ: на 512 МБ разбор тома
на 50 МБ убивается по OOM молча, без внятной ошибки.

## Локальный запуск

```bash
pip install -r requirements.txt
createdb svod
export DATABASE_URL=postgresql://postgres:postgres@localhost:5432/svod
export STORAGE_BACKEND=local          # файлы в var/files, без облака
export INLINE_WORKER=1                # разбор в потоке веб-процесса, без Redis
uvicorn portal.web.app:app --reload
```

С Redis (как в продакшене) — в двух терминалах:

```bash
export REDIS_URL=redis://localhost:6379/0
python -m portal.worker
uvicorn portal.web.app:app
```

## Что где

| Файл | Зачем |
|---|---|
| `agent/api.py` | Фасад пайплайна: `intake()`, `Capabilities`, прогресс. Единственная точка входа портала в `agent/` |
| `portal/models.py` | Схема БД: `org_id` и подачи (`submission`) с первого дня |
| `portal/tasks.py` | Задача воркера: скачать → разобрать → записать → прогресс |
| `portal/nomenclature.py` | Сводная номенклатура и отметки |
| `portal/flags.py` | Флаги готовности тома; какие флаги осмысленны для какого раздела |
| `portal/naming.py` | Шифр, раздел и ревизия из имени файла — **дописывать разделы сюда** |
| `portal/storage.py` | S3/R2 и локальный диск за одним интерфейсом |
| `portal/web/` | FastAPI, шаблоны, стили. Сборки JS нет |

## Границы, о которых надо помнить

- Раздел берётся из имени файла. Незнакомый шифр (`ПРК`) показывается как есть —
  добавьте его в `SECTION_LABELS` и, если нужно, в группы разделов `portal/flags.py`,
  чтобы для него считались правильные флаги.
- «N листов нечитаемы» — это листы, где текстовый слой не извлекается: скан,
  неизвестный шрифт или пустая страница. Их придётся смотреть глазами.
- Номенклатура группируется по **марке и наименованию**. Только по марке нельзя:
  в колонке марки часто стоит стандарт (`ГОСТ 8946-75`, `EN 877`), общий для сотни
  разных изделий, и сумма по нему была бы ложной.
- Портал показывает, что прислали, и не выдаёт заключений. Формулировки в
  интерфейсе выбраны так намеренно.
